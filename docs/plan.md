# 作業の一覧

sam45compat の残りの作業。方式と決めたことは [`design/standin-study.md`](design/standin-study.md) にある。
終わった項目は `[x]` にし、日付を書く。調査でわかった既存のシステムの事実は [`cosmos/observation-flow.md`](cosmos/observation-flow.md) に書く。

> 2026-11-06 時点。段階 1 の実装を止めているのは、1. 調査の上から 3 項目（MLPPS・SAM45 LC の命令・観測生データの形式）。
> 2-1 の骨組みと 2-4 の中核（時刻の対応と束ね）は、調査を待たずに始められる。

## 2. 段階 1（運用側の動作試験）

- [ ] **2-1. YATSUGATAKE 暫定 LC**: ソケットで設定・記録の開始と終了・ステータスを受け、specd を制御する。10.24 ms のスペクトルを時刻付きで一時ファイルに記録する。異常は自分のログに残す
- [ ] **2-2. MLPPS から呼ぶ python クライアント**: タイムアウトを短くし、終了コードで状態を返す
- [ ] **2-3. 指示書の変換スクリプト**: SAM45 の行から MLPPS 行（設定・記録の開始と終了・ステータス確認）を作って挿入する。観測者がアクセスできる場所に置く
- [ ] **2-4. 差し込みスクリプト**: SAM45 の各積分の区間に重なる 10.24 ms のダンプを束ね、周波数軸とスケールを変換して、マージ後の観測生データの故障した Array の分に書き込む。終わったら一時ファイルを削除する。運用側が手で実行する。段階 2 でもそのまま使えるように作る
- [ ] **2-5. 運用側の動作試験**: 設定の受け渡し・周波数軸・時刻の対応・値のスケール・ステータス確認での異常の検出を確かめる

## 3. 段階 2（本番）

- [ ] **3-1. ロギングの監視**: SAM45 のロギングの書き終わりを判定し、2-4 の処理を流用してロギングに差し込む
- [ ] **3-2. マージとの競合の回避**: マージが起動するまでに差し込みを終える
- [ ] **3-3. 元データの保全**: 差し込む前の SAM45 のロギングを残す
- [ ] **3-4. 本番の観測での確認**: QL に出るか、観測者の手順が指示書の変換だけになっているか
