## 2. 段階 1（運用側の動作試験）

- [ ] **2-1. specd の制御と記録**: SAM45 の設定（ヘッダから読んだもの）を YATSUGATAKE の bit と SET に変換し、LOAD（bit が変わるときだけ）・SET・START する。10.24 ms のスペクトルを時刻付きで一時ファイルに記録する
- [ ] **2-2. ロギングの監視**: 新しいファイルを見つけ（1 s 程度の見回り）、ヘッダの書き終わりを待って設定を読み、2-1 に渡す。観測の終わりを判定して記録を止める。異常は自分のログに残し、運用者に知らせる（2-1 と 2-2 で暫定 LC になる）
- [ ] **2-3. 差し込みスクリプト**: SAM45 の各積分の区間に重なる 10.24 ms のダンプを束ね、周波数軸とスケールを変換して、マージ後の観測生データの故障した Array の分に書き込む。終わったら一時ファイルを削除する。運用側が手で実行する。段階 2 でもそのまま使えるように作る
- [ ] **2-4. 運用側の動作試験**: 設定の読み取り・準備の時間（30 s に収まるか）・周波数軸・時刻の対応・値のスケール・異常の通知を確かめる

## 3. 段階 2（本番）

- [ ] **3-1. ロギングへの差し込み**: 2-3 の処理を流用し、観測が終わったらロギングの故障した Array の分に差し込む
- [ ] **3-2. マージとの競合の回避**: マージが起動するまでに差し込みを終える
- [ ] **3-3. 元データの保全**: 差し込む前の SAM45 のロギングを残す
- [ ] **3-4. 異常の印**: 差し込むデータに異常の印を付ける（フラグの欄があれば）
- [ ] **3-5. 本番の観測での確認**: QL に出るか、観測者の手順が変わっていないか
