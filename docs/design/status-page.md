# 状態のページ（暫定 LC と RFSoC）

運用中の暫定 LC と RFSoC（specd）の状態を、所内 LAN のブラウザから 1 秒ごとに見るためのページ。
検討と、決めたこと（2026-11-11）。

## 決めたこと（2026-11-11）

| 項目 | 決定 | 理由 |
|---|---|---|
| 形 | **暫定 LC が状態を JSON に書き（`status.py`）、Apache は静的なファイルとして配る**。ページ（`tools/status/index.html`）が 1 秒ごとに JSON を読む | Apache に CGI・WSGI・WebSocket を足さずに済む。1 秒の間隔なら、ページから取りに行けば十分 |
| specd の状態の取り方 | **暫定 LC の中で、命令と同じロックの下で `STATUS` を取る**（`board.status_nowait`）。LC が制御の口を使っている間（LOAD など）は飛ばし、前の値に古さを添えて出す | specd の制御の口は**同時に 1 接続だけ**。ほかのプログラムが毎秒つなぐと、LC の準備（LOAD・SET・START）が `ERR BUSY` で失敗しうる |
| 止まったことの見つけ方 | JSON に書いた時刻が **5 秒より古ければ**、ページが「暫定 LC が止まった」と出す | LC が落ちたとき、計算機ごと止まったときも、同じ仕組みで見つかる。「何も出ていない」を「正常」と見誤らない |
| 置き場所 | **`/var/www/html/status/`**（`index.html` と、LC が書く `status.json`）。URL は `http://<サーバー>/status/` | Apache の既定の置き場所の下にまとめる（2026-11-11） |
| 公開の範囲 | **所内 LAN から、認証なし**。既定の 443 番（`default-ssl.conf`。配信の `/download` と同じ口）で配り、Apache では範囲を絞らない（ファイアウォールに任せる。2026-11-12）。設定は [`tools/apache/yksp-status.conf`](../../tools/apache/yksp-status.conf)（`conf-available` に置く）。初めは所内 LAN 側の 80 番に別の VirtualHost を作るつもりだったが、仮機では使われず 443 番で見ていたので合わせた | 制御室などから誰でもすぐ見られるように。表示だけで、操作の口は無い |
| 間隔 | JSON を書き直すのも、`STATUS` を問い合わせるのも **1 秒**（設定の `status_s`・`status_board_s`） | 取得に響くなら `status_board_s` だけを延ばす（下の「確かめること」） |

## 出しているもの

- **暫定 LC**: 版（sam45compat と YATSUGATAKE。作業ツリーに手直しがある・submodule が固定の版と違うときは注意。直近の観測の bit の USR_ACCESS と specd の版。
  [`../operation/versioning.md`](../operation/versioning.md)。2026-11-12）、動いている時間、本体の 1 周の古さ（150 秒を越えたら異常。LOAD は最大 120 秒）、見回る置き場所を読めるか
- **窓の設定**: ADC・窓ごとに、肩代わりする Array、IF（ch 1..4096 の端と 2047 番目の ch）、帯域、分解能、天空周波数、ch の向き、specd に送った SET。
  LC が観測ごとに作った予定（`mapping.Plan`）から出す（specd に `GET` は打たない）。観測中でなければ直前の観測のもの（ボードは次の SET まで同じ設定）
- **今の観測**: ログ ID、状態（L1 待ち・準備中・記録中・準備に失敗）、bit、肩代わりする Array、書いた L2・無効にした L2、束ね待ち、時刻の無いダンプ
- **終わった観測**: LC を起こしてからの直近 10 個（取った版も）
- **配信・マージ**: 処理中のもの、待ちの数、最近移したもの
- **ディスク**: YKSP のロギングの置き場所・一時ファイル（`board.tmp_dir`）・配信の置き場所の空き（85 % で注意、95 % で異常）
- **通知**: `notify.py` の通知の直近 30 個（メールなどの手段が決まるまで、ここで見る）
- **RFSoC のボード**（設定の `board.hk_port` があれば）: 温度（PS の LPD・FPD、PL）、電流（INA220。VCCINT ほか）、CPU ごとの使用率、負荷、メモリ・`/dev/shm`・SD カードの使用率、
  AMS の電圧。ボードの上の常駐（`tools/boardhk.py`）から HTTP で読む。閾値は仮（温度 65 ℃ で注意・75 ℃ で異常、VCCINT 35 A で注意・40 A で異常。
  Wide でボードが落ちたときは VCCINT 41.8 A・70.8 ℃ で上昇中だった）。取得の CPU（CPU3）は使い切るのが普通なので、色で知らせない
- **RFSoC**: specd の `STATUS`（状態、時刻（1PPS）、PPS のずれ（`pps_drift`・`pps_n`・`pps_tol`。許容の半分で注意・越えたら異常。2026-11-13）、ADC ごとの TP、0 であるべき数（`miss`・`kgap`・`drop`・`pl_drop` など）、`health`・`flags`、読み出しの 1 周、溜まり、データの口）と、LC の受け側がつながっているか。
  鍵の意味は YATSUGATAKE の `docs/user/specd.md` の「STATUS の見方」
- **周波数の基準（10 MHz）**（2026-11-11）: LC が受けた記録の `health` の [1]（1PPS の間隔が 256,000,000 ± 1 ビートを外れた。コアの
  `hw/common/time_core.v`）を見る（`recorder.RefWatch`）。10 MHz が来ていない・specd が `--clkin 0` でないと fs が ppm 単位でずれ、
  この印が立つ（コアの ADR 0006・0008。レジスタの「ロック」では判定できない）。直近 60 秒にこの印が無ければ OK、あれば「ずれている」（異常）、
  [0]（1PPS が来ていない）があれば「判定できない」。**記録を受けている間（観測中）しか判定できない**。観測していなければ最後の記録の時点の判定を出す。
  `board.no_pps` の間は判定しない。LMK04828 のホールドオーバがあるので、10 MHz を抜いてもすぐには外れない

LC を起こし直すと、終わった観測と通知の一覧は空に戻る（記録はしない。過去を見るのは journal と YKSP のロギング）。

## QL（スペクトル。2026-11-11）

`http://<サーバー>/ql/`。状態のページと同じ形で、暫定 LC が `ql.json`（設定の `ql_path`）を 1 秒ごとに書き、ページ（`tools/ql/index.html`）が読む（`ql.py`）。窓ごと（A05〜A08・A21〜A24）に 2 段:

| 段 | 中身 | 更新 |
|---|---|---|
| 生 | 今の観測の 10.24 ms のダンプ（`DiskDumps`）の直近 `ql_avg_s` 秒（1 秒）の平均。dB か線形。「表示しない」で全 Array の生の段を隠す（2026-11-12） | 1 秒ごと。観測していない間は出ない（ボードのデータを溜めていない） |
| Ta* | 積分ごとの L2 から、窓ごとに直近の OFF を覚え、ON が来たら Tsys × (ON − OFF) / OFF。Tsys は L2 に書いた値（SKY の後に決まる）。それまでは (ON − OFF) / OFF | ON の積分が束ねられるたび。観測が終わっても最後の値を残す |

- 横軸は Vlsr（既定。2026-11-12）・天空周波数（L2 の ch の順。ch 1 と ch 4096 の値から線形）・IF・ch を選べる。速度の情報が無ければ天空周波数。
  Vlsr = dstrv + c·(1 − f / f_rest)（電波の定義）。45m のロギングの周波数はドップラー追尾した系（dstrv で動く天体の線が静止周波数に来る）なので、
  これで速度になる。サンプル（2026-09-10 の R Cas、SiO v=1 J=1−0 を 43.122080 GHz）でピークが 24.95 km/s に出ることを確かめた（2026-11-11）。
  f_rest の既定は L1 の `dcent_freq`。観測者が丸めた値を入れていることがある（サンプルは 43.122 GHz で、0.56 km/s ずれる）ので、
  ページで窓ごとに入れられる（ブラウザに覚える）。`ivdef`・`ivref`（速度の定義・基準）の値の意味は未確認（サンプルは 1・1）。1 以外なら注意を出す
- **随時の Ta***（2026-11-11 に足し、2026-11-12 にページから外した）: 生のスペクトルを ON とみなして直近の OFF と比べ、1 秒ごとに出していた。
  LC は今のデータが ON かを積分が終わるまで知らず、OFF・R・SKY の間も ON とみなした値を出すので使わないことにした。
  Ta* は積分ごとだけ（ON の積分のたびに更新し、OFF・R・SKY の間は直前の ON を出し続ける。遅れは積分 1 つぶんと束ねる待ち）。
  LC（`ql.py` の `live_ta`）は今も `ql.json` に計算して載せているが、ページは使わない。
  ページの上に、ロギングで見たスキャンの種類ごとの積分の数を出す（OTF のスキャンの名前が ON・OFF か、まだ確かめていない。サンプルが無い）
- **観測が終わった後**（2026-11-11）: 生の段は、その観測の最後に出した値（`last_realtime`。観測の ID を添える）を次の観測の最初のダンプまで出す。
  Ta* の段は積分ごとの最後の ON を出す。LC を起こし直すと消える
- **並べ方**（2026-11-12）: 窓は Array の番号の順（4 列で A05〜A08 と A21〜A24 が 1 段ずつ）。列は「自動」で幅に合わせて最大 4（1 枚 380 px が目安）、
  1〜4 を選ぶこともできる。上のチェックで Array ごとに表示・非表示を切り替え、表示するものだけを詰めて並べる（列は表示する数より多くしない）。
  横軸・生・列の選択と隠した Array はブラウザに覚える（`localStorage`。見る人ごと）
- **ビニング**（2026-11-12）: ページの「ビニング」で、隣り合う 1・2・3・4・5・10・15・20・25・30 ch ずつ平均して描く（全 Array 同じ。ブラウザに覚える）。
  生は線形で平均してから dB にする。割り切れない端は、ある分だけで平均する。そのため LC は ch を減らさずに送る（`ql_nbin` の既定を 1024 から 4096 にした。
  2048 ch の Array は 2048 のまま）。古い LC が点を減らして送っていれば、ページは 1 点あたりの ch で割って点の数にする
- `ql.json` は窓 8 つで約 620 KB（ch を減らさないため。随時の Ta* を外して少し減らした）。見る人 1 人あたり毎秒それだけ読む。
  Apache で圧縮すると約 180 KB になる（`tools/apache/yksp-status.conf` の `DEFLATE`。所内 LAN なら圧縮しなくても足りる量）
- グラフは canvas に自前で描く（所内 LAN から CDN に届かなくても動くように）
- 表示だけ。Ta* は QL 用の簡易なもので、観測生データ（YKSP）の較正とは別。OTF でも直近の OFF で割るだけ

## 気をつけること

- **観測者の名前が見える**: ログ ID の欄・移したファイルの名前に `<group>`（LDAP のアカウント名）・`<project>` が含まれる。
  所内 LAN に見せる前提で決めた（2026-11-11）。所外に出すなら、これを伏せる
- **人が specctl でつないでいる間**: 状態のページの問い合わせは `ERR BUSY` になり、ページは「応答なし」と出す（前の値は残る）。
  逆に、状態のページの問い合わせ（数 ms）とぶつかった specctl が `ERR BUSY` を受けることがある。打ち直せばよい。
  調べもので長く specctl を使うときは、設定の `status_board_s` を延ばして LC を起こし直すか、我慢する
- **表示だけ**: ページの「異常」は運用の判断に使っていない。無効にする・知らせるのは今までどおり `lc.py` が行う。
  状態のページが書けなくても（置き場所が無いなど）、LC は止めない（ログに 1 回だけ出す）

## 確かめること（実機）

- [ ] 毎秒の `STATUS` が取得に響かないか: RUN の間の `loop_max_ms`・`miss`・`drop` を、`status_board_s` を 1 秒と 0（止める）で比べる。
  響くなら 2〜5 秒にする
- [ ] 1PPS なしの試験（`board.no_pps`）では「時刻（1PPS）」が注意（黄）になる。本番の配線で緑になること
- [ ] 10 MHz・1PPS をつないで `--clkin 0 --ref 10` で起こし、「周波数の基準」が OK になること。`--clkin` を外す（ボードの水晶）と「ずれている」になること

## やめた案

- **ボードの状態を specd の命令（HK）で返す**（コア側）: 制御の口で取れ、ボードに別のものを置かずに済む。汎用の機能としてコアに入れる候補。
  ただし版の上げと試験が要るので、今はボードに別の常駐（`tools/boardhk.py`、`WORKAROUND(core):`）を置いた（2026-11-11）
- **LC から ssh でボードの sysfs を読む**: ボードに何も置かずに済むが、鍵の用意と、ssh が詰まったときの扱いが面倒

- **CGI などで、ページを開くたびに specd へ問い合わせる**: 制御の口の 1 接続の制限で、LC の準備とぶつかる。見る人の数だけ問い合わせが増える
- **Prometheus と Grafana**: 履歴とグラフ、知らせまでできるが、今の段階では入れるものが多い。
  履歴が欲しくなったら、`status.json` を読む exporter を足せば移れる
- **10 MHz を観測していない間も見る**: time_core の 1PPS の間隔（`PT_INT`）や外れた数（`BAD`）を読めば IDLE でも ppb で出せるが、
  `STATUS` に無く、ボードの別のプロセスから `/dev/mem` で読むと specd の読み（`PT_LO` で組を固定する）とぶつかりうる。コアの `STATUS` に足す候補
- **specd に読み出し専用の状態の口を足す**（コア側）: 制御の口の制限を根本から避けられ、汎用の機能としてコアに入れる候補にはなる。
  ただし使う版を固定しているので、今は LC の中で済ませた（最終版で検討する）
