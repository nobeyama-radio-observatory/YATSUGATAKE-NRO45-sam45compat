# 観測生データ（YKSP）の配信

マージで作った観測生データ（YKSP）を、観測者に渡すための検討と、決めたこと。
今の観測生データ（SAM45）は nrodb というウェブアプリで配っている。nrodb は仕様の面から YKSP の観測生データを入れにくいので、
暫定の配信を簡単に作る（2026-11-10）。

## 要る機能（2026-11-10）

- ウェブブラウザ、またはコマンドラインからアクセスする
- 機能は**検索**と**ダウンロード**
- **観測者は自分のデータだけ**を検索・ダウンロードできる。他人のデータは検索もダウンロードもできない

## 決めたこと（2026-11-10）

| 項目 | 決定 | 理由 |
|---|---|---|
| アクセスできる範囲 | **所内 LAN の PC からだけ** | |
| 認証 | **所内 LAN の共有計算機と同じ LDAP** | 観測者に新しいアカウントを配らずに済む |
| 持ち主の決め方 | **ロギングの名前の `<group>` が LDAP のアカウント名**。ログインした人は、自分の `<group>` の下の `<project>` を**全部**見られる | `<project>` は観測者が付けたフォルダの名前で、`<group>` の下にある |
| 置き場所 | **ストレージ・制御サーバー**（暫定 LC と同じ計算機）のストレージのディスク | 配信だけのために計算機を増やさない。下の「同じ計算機に置く条件」を守る |
| 保管の期間 | **まずは 1 年** | |

## 作り方（Apache の LDAP 認証とフォルダの一覧。2026-11-10 決定）

仮機で動くことを確かめた（[`../operation/server-setup-provisional.md`](../operation/server-setup-provisional.md) の 5.2）。設定のひな形は [`tools/apache/yksp-download.conf`](../../tools/apache/yksp-download.conf)。

- 置き場所は **`/srv/download`**（ストレージのディスク）。その下を次の形にする（2026-11-10）:

  | 中身 | 置き場所 |
  |---|---|
  | 観測生データ（マージの出力）の OTF | `/srv/download/<group>/<project>/otf/` |
  | 観測生データ（マージの出力）の PSW | `/srv/download/<group>/<project>/psw/` |
  | YKSP のロギング | `/srv/download/<group>/<project>/logging/` |

  `<group>` は LDAP のアカウント名（ユーザー ID）。OTF か PSW かは、どの bklog（`sam45otf/`・`sam45psw/`）から来たかで決める
- Apache の `mod_authnz_ldap` で LDAP にログインさせ、**`<group>` とログインした名前が同じときだけ**通す
  （`<DirectoryMatch "^/srv/download/(?<grp>[^/]+)">` ＋ `Require expr "%{REMOTE_USER} == %{env:MATCH_GRP}"`）。
  URL ではなくファイルの実際の場所で判定し、`%2e%2e`・`//` などの書き方で回り込ませない。頭の一覧（ほかの `<group>` の名前）は見せない
- **ブラウザ**: `https://<サーバー>/download` を開き、ログインすると自分のフォルダ `/download/<アカウント>/` へ転送される。フォルダの一覧（`Options +Indexes`）から落とす（2026-11-10）
- **コマンドライン**: 共有計算機にある `curl`・`wget` で取る（`wget -r -np --user=<アカウント> --ask-password https://<サーバー>/download/<アカウント>/<project>/`）。新しいツールは作らない
- **検索**: まずはフォルダの一覧とファイル名（指示書名・ログ ID）で足りるかを観測者に試してもらう。
  天体名・日付などで探したい声があれば、L1 から作った一覧で検索するページを 1 つ足す
- アクセス制限は、**毎回サーバーの側で**確かめる（画面に出さないだけの制限にしない）。だれがいつ何を取ったかは Apache のログに残る

### 気をつけること

- Basic 認証は LDAP のパスワードをそのまま送るので、**LAN の中でも HTTPS にする**（所内の証明書か自己署名）。LDAP との間も LDAPS か StartTLS にする
  （仮機は今 `ldap://` で、Apache と LDAP の間が平文。2026-11-10）
- ログインできるのは、`AuthLDAPURL` の絞り込みに当てはまるアカウントだけ。観測者のアカウントが当てはまるようにする
- 「`<group>` は 1 人のアカウント」が前提。共同研究者に見せたいときは別の仕組みが要る（今は求められていない）

### 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| nrodb に入れる | 仕様の面から YKSP の観測生データを入れにくい |
| Nextcloud などのファイル共有を LDAP につなぐ | この要件ならフォルダの一覧で足りる。運用するソフトが増える |
| 自作のウェブアプリ（検索の DB ＋ トークンで使うコマンドラインのツール） | 認証と認可を自分で作る責任が出る。検索がファイル名で足りなかったときに考える |
| SFTP（Unix の権限） | ブラウザから使えない |

## 同じ計算機に置く条件（2026-11-10）

ストレージ・制御サーバーは、観測中に 10.24 ms の記録（≒ 12.8 MB/s、一時ファイルは ≒ 46 GB/時）を受ける。配信がこれを邪魔しないようにする。

| | 構成 |
|---|---|
| ディスク | **一時置き場**（`/home/yk/bklog`。追記中のロギング、10.24 ms の一時ファイル（`board.tmp_dir` = `/home/yk/bklog/tmp`））と、**ストレージ**（書き終えたロギングを移す先、観測生データ）を別のディスクにする。ストレージは **RAIDZ** で、一時置き場とは別にマウントする（マウント先は決める）（2026-11-10） |
| NIC | **3 本以上**: ボード用・SAM45 のロギング（bklog）用・観測者のダウンロード用 |

- Apache は別の利用者で動かし、ストレージの観測生データを**読むだけ**にする。暫定 LC の利用者（yk）のファイル・bklog には触らせない
- ダウンロードの速さを抑え（`mod_ratelimit`）、Apache は低い優先度（`nice`・`ionice`）で動かす
- ファイアウォールで、HTTPS はダウンロード用の NIC・所内 LAN からだけ通す
- 記録で取りこぼしが出たら、配信だけを別の計算機に移す（ストレージを NFS で渡せば、置き方は変えずに済む）

## データの流れ

1. 暫定 LC が YKSP のロギングを**一時置き場**（`/home/yk/bklog`）に書く（観測中に追記）
2. ED を書いたら、別スレッドで（見回りを止めずに）YKSP のロギングを `/srv/download/<group>/<project>/logging/` に移す
3. **マージの計算機**に ssh で入り、マージスクリプトを走らせる（2026-11-11 に仕様が決まった）。
   マージの計算機は `/srv/download` を NFS でマウントしていて（マウント先は `/cosmos3/45m/bklog/yksp`）、
   `logging/` のロギングを読み、`<group>/<project>/` の直下に観測生データを書く
4. マージの前後で `<project>/` の直下のファイルを比べ、増えたファイルを `otf/` または `psw/` に移す
5. マージに失敗したら運用者に知らせる。ロギングは `logging/` にあるので、後から手でやり直せる
6. 1 年を過ぎたものを消す（ロギングも同じ期間でよいかは決める）

### マージ（2026-11-11）

| | |
|---|---|
| スクリプト | PSW: `mergePSW-Y.sh`、OTF: `mergeOTF-Y.sh`（マージの計算機にある） |
| 引数 | `<group> <project> <ログ ID> <置き場所>/ <ロギングのフォルダ>/`。置き場所とロギングのフォルダは、マージの計算機から見たパス（`/cosmos3/45m/bklog/yksp/`、`/cosmos3/45m/bklog/yksp/<group>/<project>/logging/`）。ロギングはフォルダで渡し、ログ ID で選ばせる（2026-11-11 に訂正） |
| 出力 | `/cosmos3/45m/bklog/yksp/<group>/<project>/` の直下（= `/srv/download/<group>/<project>/`） |
| 起動 | 暫定 LC の利用者（yk）の、マージ専用の鍵（パスフレーズ無し）で ssh。マージの計算機の `authorized_keys` で、`from=`（制御サーバーの管理者のセグメント側の IP）と `restrict` で絞る |
| NFS | 制御サーバーが `/srv/download` を、**マージの計算機のセグメントにだけ**読み書きで公開する（`all_squash`・`anonuid`/`anongid` = yk）。そのセグメントには管理者しか入れず、観測者は NFS では入れない（Apache を通してだけ取る）。yk として書かせるのは、暫定 LC がマージの出力を移し、0644 に直せるように |

### 実装

実装は `src/sam45compat/deliver.py`（設定の `deliver_root`・`merge_cmd`・`merge_root`。2026-11-10、マージの手順は 2026-11-11）。

- 別のディスクへは、写して（`.<名前>.part`）から名前を付け替える。途中のファイルを Apache から見せない
- 移した先に同じ名前があれば上書きせず、元を一時置き場に残して知らせる
- ファイルは 0644、フォルダは 0755（Apache の利用者が読む）
- `merge_cmd` は引数の並び。PSW と OTF でスクリプトが違うので `{"psw": [...], "otf": [...]}` で書く（`config/bklog.json`）。
  `{logging}`（マージの計算機から見た、`logging/` に移した後のロギング）・`{root}`（`merge_root`）・`{kind}`・`{log_id}`・`{obs}`・`{group}`・`{project}` を差し込む。
  `null` ならマージを飛ばし、ロギングだけ移す
- ssh は引数を空白でつないで向こうのシェルに渡すので、差し込む値は英数字と `_./+-` だけにする（ほかの文字があれば、マージせずに知らせる）
- マージの途中のファイルは `<project>/` の直下で Apache から見える（本人にだけ）。失敗したときに残ったファイルは振り分けず、通知に名前を出す
- 暫定 LC を止めると、待っていた分は一時置き場に残る。マージに失敗した分は `logging/` にある。どちらも手で:
  `python3 -m sam45compat.deliver <YKSP のロギング> --kind psw --config <設定>`（設定の `deliver_root`・`merge_cmd`・`merge_root` を使う）
