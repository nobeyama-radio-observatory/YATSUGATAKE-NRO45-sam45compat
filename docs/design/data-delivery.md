# 観測生データ（YKSP）の配信

マージで作った観測生データ（YKSP）を、観測者に渡すための検討と、決めたこと。
今の観測生データ（SAM45）は nrodb というウェブアプリで配っている。nrodb は仕様の面から YKSP の観測生データを入れにくいので、
暫定の配信を簡単に作る（2026-11-10）。

## 要る機能（2026-11-10）

- ウェブブラウザ、またはコマンドラインからアクセスする
- 機能は**検索**と**ダウンロード**
- **観測者は自分のデータだけ**を検索・ダウンロードできる。他人のデータは検索もダウンロードもできない

## 決めたこと（2026-11-10）

| 項目 | 決定 | 理由 |
|---|---|---|
| アクセスできる範囲 | **所内 LAN の PC からだけ** | |
| 認証 | **所内 LAN の共有計算機と同じ LDAP** | 観測者に新しいアカウントを配らずに済む |
| 持ち主の決め方 | **ロギングの名前の `<group>` が LDAP のアカウント名**。ログインした人は、自分の `<group>` の下の `<project>` を**全部**見られる | `<project>` は観測者が付けたフォルダの名前で、`<group>` の下にある |
| 置き場所 | **ストレージ・制御サーバー**（暫定 LC と同じ計算機）のストレージのディスク | 配信だけのために計算機を増やさない。下の「同じ計算機に置く条件」を守る |
| 保管の期間 | **まずは 1 年** | |

## 作り方（案: Apache の LDAP 認証とフォルダの一覧）

まだ案。LDAP の接続の条件がわかったら決める。

- 観測生データ（YKSP）を `<ストレージ>/<group>/<project>/<ファイル>` に置く
- Apache の `mod_authnz_ldap` で LDAP にログインさせ、**URL の頭の `<group>` とログインした名前が同じときだけ**通す
  （`<LocationMatch "^/yksp/(?<grp>[^/]+)/">` ＋ `Require expr "%{REMOTE_USER} == %{env:MATCH_GRP}"`）。
  頭の一覧（ほかの `<group>` の名前）は見せない
- **ブラウザ**: `https://<サーバー>/yksp/<アカウント>/` を開き、フォルダの一覧（`Options +Indexes`）から落とす
- **コマンドライン**: 共有計算機にある `curl`・`wget` で取る（`wget -r --user=<アカウント> --ask-password ...`）。新しいツールは作らない
- **検索**: まずはフォルダの一覧とファイル名（指示書名・ログ ID）で足りるかを観測者に試してもらう。
  天体名・日付などで探したい声があれば、L1 から作った一覧で検索するページを 1 つ足す
- アクセス制限は、**毎回サーバーの側で**確かめる（画面に出さないだけの制限にしない）。だれがいつ何を取ったかは Apache のログに残る

### 気をつけること

- Basic 認証は LDAP のパスワードをそのまま送るので、**LAN の中でも HTTPS にする**（所内の証明書か自己署名）。LDAP との間も LDAPS か StartTLS
- 「`<group>` は 1 人のアカウント」が前提。共同研究者に見せたいときは別の仕組みが要る（今は求められていない）

### 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| nrodb に入れる | 仕様の面から YKSP の観測生データを入れにくい |
| Nextcloud などのファイル共有を LDAP につなぐ | この要件ならフォルダの一覧で足りる。運用するソフトが増える |
| 自作のウェブアプリ（検索の DB ＋ トークンで使うコマンドラインのツール） | 認証と認可を自分で作る責任が出る。検索がファイル名で足りなかったときに考える |
| SFTP（Unix の権限） | ブラウザから使えない |

## 同じ計算機に置く条件（2026-11-10）

ストレージ・制御サーバーは、観測中に 10.24 ms の記録（≒ 12.8 MB/s、一時ファイルは ≒ 46 GB/時）を受ける。配信がこれを邪魔しないようにする。

| | 構成 |
|---|---|
| ディスク | **一時置き場**（`/home/yk/bklog`。追記中のロギング、10.24 ms の一時ファイル（`board.tmp_dir` = `/home/yk/bklog/tmp`））と、**ストレージ**（書き終えたロギングを移す先、観測生データ）を別のディスクにする。ストレージは **RAIDZ** で、一時置き場とは別にマウントする（マウント先は決める）（2026-11-10） |
| NIC | **3 本以上**: ボード用・SAM45 のロギング（bklog）用・観測者のダウンロード用 |

- Apache は別の利用者で動かし、ストレージの観測生データを**読むだけ**にする。暫定 LC の利用者（yk）のファイル・bklog には触らせない
- ダウンロードの速さを抑え（`mod_ratelimit`）、Apache は低い優先度（`nice`・`ionice`）で動かす
- ファイアウォールで、HTTPS はダウンロード用の NIC・所内 LAN からだけ通す
- 記録で取りこぼしが出たら、配信だけを別の計算機に移す（ストレージを NFS で渡せば、置き方は変えずに済む）

## データの流れ

1. 暫定 LC が YKSP のロギングを**一時置き場**（`/home/yk/bklog`）に書く（観測中に追記）
2. ED を書いたら、YKSP のロギングを**ストレージ**に移す
3. マージを起動し、観測生データ（YKSP）をストレージの `<group>/<project>/` に書く
4. 1 年を過ぎたものを消す（ロギングも同じ期間でよいかは決める）
